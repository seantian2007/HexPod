# HexPod Academy

An interactive, bilingual (English / 中文) course that follows this robot's build, from the first servo to a hexapod walking under gamepad control.
Each stage page has plain-language explanations, drag-to-explore widgets, photos and clips from our own build, and a practice list that ends in a reward (something moves).

```
learn/
├── site/                     # the website: static files; only the notebooks need building
│   ├── index.html            # landing page
│   ├── i18n.js               # landing page text
│   ├── hexview.js            # tiny 3D hexapod renderer (shared by pages and the notebook)
│   ├── assets/
│   │   ├── site.css          # shared styles (light + dark)
│   │   └── core.js           # shared runtime: top bar, stage strip, language switch, pager, clips, canvas helpers
│   ├── build/                # "Build the robot": parts, assembly, wiring, first power, messenger firmware
│   ├── stage0/ … stage6/     # one folder per stage: index.html + i18n.js (all text) + page.js (widgets)
│   │   └── notebook/         # in every stage folder; generated by build.sh (not committed)
│   └── media/
│       ├── ours/             # photos, plots and clips from our build
│       ├── rk/               # images and clips from rookidroid/hexapod (GPL-3.0)
│       └── CREDITS.md
├── notebooks/                # practice notebooks (marimo): exercises + checkers + rewards
│   ├── stage0_servo.py       # servo and power

```

## How to run

From the `code/` folder:

```bash
cd learn/site && python3 -m http.server 8000
```

Open <http://localhost:8000/>. The language switch is in the top-right corner of every page.

Every page works this way. The practice notebooks (one per stage, 0–6) need building first, because they run Python inside the browser:

```bash
pip install marimo          # once
bash learn/build.sh         # builds all seven notebooks into site/stageN/notebook, then serves the site
```

Each build is about 28 MB, which is why they are not committed. To work through a notebook locally instead (needed for the "run it on the real robot" parts, which talk to the robot through `utils/link.py`):

```bash
marimo edit learn/notebooks/stage3_ik.py      # or any other stage
```

Every notebook works the same way: edit the cells marked ✏️, and a checker under each one turns green when your code is right. Hints open one at a time; the last one is the full answer. Pass all checkpoints to unlock the reward (something moves on the simulated robot). The `_solved` copies are for checking the checkers, not for reading first.

## Adding a language

- Pages: in each `i18n.js`, copy the `en` block, give it a new key (for example `es`) and translate it. Shared words (navigation, buttons) are in `COMMON_I18N` in `assets/core.js`; add the language's name to `LANG_NAMES` there.
- Notebooks: in the last cell of each notebook, copy the `"en"` block of `TEXT`, and add the option to the `lang` dropdown in the second cell.
